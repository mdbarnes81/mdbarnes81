Drift alerts: product vs outline

The question pool lags the product. Where docs changed recently, know both the "exam-era" answer and the current one.

Content exclusionExam-era docs: agent mode in IDEs, Copilot CLI and coding agent do NOT support content exclusion. Changelog 2 Sep 2026: exclusions now GA in the Copilot app and CLI. Current docs: IDE agents, CLI and app block access via Copilot tools but "might not detect indirect file access". If a question asks which features don't honour exclusions, the classic answer is agent mode / CLI / coding (cloud) agent.
Naming"Copilot coding agent" is now Copilot cloud agent in GitHub Docs. "Copilot Edits" / Edit mode is deprecated in VS Code (use Agent mode for multi-file edits) but still named in the outline.
BillingPremium-request billing is now labelled legacy; plans use GitHub AI Credits with pooled allowances for Business/Enterprise and a new Copilot Max tier. Older practice questions will talk about "premium requests".
Code review12 Jun 2026: the 4,000-character read limit on instruction files for code review was removed and content exclusions now apply to code review. Older material still cites 4,000.
MCP config.vscode/mcp.json (top-level servers) is the classic VS Code location. Newer VS Code docs prefer portable .mcp.json / ~/.copilot/mcp-config.json (top-level mcpServers).
IP indemnityExam answer: Business/Enterprise + Block + unmodified. But Microsoft's Customer Copyright Commitment dropped the filter requirement for GitHub offerings on 3 Apr 2026, and new GitHub subscriptions moved to the Generative AI Services Terms on 5 Mar 2026.
Training on user dataBefore 24 Apr 2026, personal-plan data was not used for training by default (the setting was locked off). Since then Free / Pro / Pro+ are opted in by default. Older material saying "individual users can opt out", or "no plan's data is used for training", reflects one of the two eras. Business/Enterprise never changed.
Plan modePlan / Agent / Ask is the current mode picker. Plan uses read-only tools, then hands off to an implementation agent.

Instruction precedence (Copilot Chat on GitHub.com)

  1. Personal instructions (highest)
  2. Repo path-specific *.instructions.md
  3. Repo-wide copilot-instructions.md
  4. Agent instructions (AGENTS.md)
  5. Organisation instructions (lowest)
  • All relevant sets are sent; precedence only matters on conflict, and conflict resolution is non-deterministic.
  • Org instructions only work on GitHub.com: Chat, code review, cloud agent.
  • Personal instructions are GitHub.com Chat only (CLI uses local files).
  • Nested AGENTS.md: nearest in the tree wins.
  • Root AGENTS.md + copilot-instructions.md: both used.

MCP essentials

  • Used from Agent mode (tools). Transports: stdio (local command), streamable HTTP, SSE (legacy).
  • VS Code format: .vscode/mcp.json with top-level "servers". Portable format uses "mcpServers".
  • GitHub MCP server is preconfigured in Copilot CLI and for the cloud agent; add it yourself in VS Code.
  • VS Code caps a request at 128 tools; deselect tools to stay under.
  • Workspace MCP config respects Workspace Trust (Restricted mode stops servers).

Code review, Spaces, Spark, PR summaries

Copilot code review

  • Request: PR → Reviewers → Copilot. REST: request copilot-pull-request-reviewer[bot].
  • Automatic reviews via repo/org rulesets ("Review new pushes" for re-reviews) or personal setting.
  • Customise with copilot-instructions.md and path-specific *.instructions.md. "Coding guidelines" feature is deprecated in favour of these.
  • "Fix with Copilot" hands a comment to the cloud agent (both must be enabled).
  • Runs on GitHub Actions; may repeat resolved comments on re-review.

Copilot Spaces

  • Anyone with a Copilot licence, including Free.
  • Sources: repos, files, PRs, issues, free text, images, uploads. GitHub sources auto-sync; repos use latest main.
  • Org spaces: roles admin / editor / viewer or "No access". Personal spaces: private, specific users or public (view-only).
  • Used from the IDE via the remote GitHub MCP server.
  • Replaced knowledge bases (Enterprise-only, org-owner-created, Markdown-only), which were retired from 1 Nov 2025. Old questions may still ask about KBs.

GitHub Spark & PR summaries

  • Spark: natural language → full-stack app. Pro+ and Enterprise. Public preview.
  • Enterprise: disabled by default; enable via AI controls / Copilot policies. Not available with data residency.
  • PR summaries: Copilot drafts the pull request description from the diff.

2 · Organisation settings, audit log & REST API part of 25–30%

Policy model

  • Enterprise owner sets a policy (Enabled / Disabled) or chooses "Let organizations decide" (older docs and questions: "No policy") to delegate to org owners. Org owners cannot override an enterprise decision.
  • Org settings: Policies (features, privacy) and Models (extra models that may cost more). Enterprise UI: AI controls → Agents / Copilot / MCP.
  • Cloud (coding) agent and MCP servers on GitHub.com are off by default.
  • "MCP servers in Copilot" policy covers GA MCP surfaces; preview MCP in editors is governed by Editor preview features. Visual Studio agent mode + MCP also sit under Editor preview features.
  • Suggestions matching public code: if enterprise picks "No policy", each org can set it; org members can't change it personally.

User licensed by several orgs with conflicting policies

RuleApplies to
Least restrictive wins (any org enables → enabled everywhere)Most features: editor preview features, MCP servers, cloud agent, Copilot CLI, Spark, model policies, commit messages
Most restrictive winsOnly the most sensitive, e.g. access to Copilot metrics via API
TrapIntuition says "most restrictive wins". For most Copilot features it is the opposite.

Audit log

  • Search action:copilot for all Copilot events; e.g. action:copilot.cfb_seat_assignment_created = seat assigned.
  • actor:Copilot = agent activity (field actor_is_agent: true; user = who triggered it).
  • Retains 180 days; can stream (Enterprise Cloud).
  • Records settings, policy and seat changes. Does NOT contain prompts or client-side session data.
  • Org owners and enterprise admins (or "Read enterprise audit logs" role).

Licence & billing mechanics

  • Assigning a Business/Enterprise seat auto-cancels a personal Pro / Pro+ / Max plan, with a prorated refund. Personal and org policies therefore never conflict.
  • While licensed by an org, the user cannot change their plan or billing cycle.
  • Business and Enterprise seats on one user: only the Enterprise seat is billed.
  • User counted once in total_seats; multi-org billing picks one org at random monthly.
  • Remove seat or user: access lost immediately; billing stops at end of cycle; no refund. Remove all seats = org plan cancelled.
  • Org removed from enterprise: its users lose access unless licensed elsewhere.
  • Copilot-only ("standalone") enterprise: IdP integration without GHE licences, but REST endpoints that need an organisation don't work.

3 · Data & architecture 10–15%

Prompt construction pipeline (inside your IDE, before anything leaves)

A fuller version of the common "collect → tokenise → assemble → send" diagram. The extra stages are the ones questions probe: exclusions are applied before sending, context is ranked and trimmed to a token budget, and what gets assembled differs by mode.

Client side: Copilot extension / CLI
1Gather
  • Code before and after cursor (FIM)
  • File name and type, language, frameworks
  • Open tabs (neighbouring tabs)
  • Project structure and paths
  • Chat: selection, # refs, @workspace / #codebase search, chat history
  • Instruction files
2Filter
  • Content exclusions remove excluded files (Business / Enterprise; exam-era: not in agent mode / CLI)
  • Closed files never seen by inline completions
  • IDE may still leak semantic info (types, hovers)
3Rank
  • Snippets scored for relevance to the cursor or question
  • Prioritised, deduplicated, ordered
4Budget
  • Tokenise to measure size
  • Trim to fit the model's context window
  • Lowest-priority context dropped first; long chats lose early detail
5Assemble
  • Ordered prompt: instructions, then context, then the request
  • Shape depends on mode (see below)
HTTPS (TLS)
GitHub-owned Azure tenant
6Proxy
  • Toxicity, relevance, prompt-hacking checks
  • Then LLM, then outbound filters (see Life of a suggestion)

Inline completion prompt

Neighbouring-tab snippets (ranked)
File path and language
Prefix: code above cursor
▮ cursor: model fills the middle
Suffix: code below cursor

No user message: your code and comments are the prompt. That's why descriptive names, comments and open related files (the "Surround" S) matter.

Chat (Ask / Plan) prompt

System instructions (GitHub-defined, not editable)
Custom instructions (personal, repo, path-specific, org)
Collected context (selection, #refs, search results)
Chat history (earlier turns in thread)
User message (+ /command, @participant)

Custom instructions are added to every chat request automatically; prompt files are added only when you invoke them.

Agent mode / CLI prompt

System instructions
Custom instructions, AGENTS.md, skills
Tool definitions (built-in + MCP)
Context + history + tool results
User task

Loop: the model calls a tool, the result is added, and the prompt is rebuilt and resent until done. Every iteration goes through steps 1 to 6. INFERRED tool layering isn't documented in detail by GitHub.

TrapTokenisation isn't a security or privacy step. It only measures and encodes text for the model. Privacy controls on the client side are content exclusion (step 2); everything else happens on the proxy (step 6).
Exam angle"Why did Copilot ignore my other module?" Not open, excluded, or ranked out by the token budget. Fixes: open the file, reference it with #file, start a fresh chat, narrow the question.

LLM and Copilot limitations

  • Training cut-off: may suggest deprecated APIs or old versions.
  • Context window is finite: only part of the codebase is sent; long chats lose early detail.
  • Non-deterministic: same prompt, different output.
  • Can hallucinate functions, packages or facts confidently.
  • Quality drops for niche languages and frameworks with little public code.
  • Not a security scanner; can reproduce insecure patterns.
  • Excluded files can still leak semantic info indirectly via the IDE (types, hovers).

Trap"Shot" = number of examples, not number of prompts. Some third-party content uses "one-shot" to mean "one concise instruction"; the official meaning is one example. Principles: the 4 S's

SMeaning
SingleOne well-defined task or question
SpecificExplicit, detailed instructions
ShortConcise, without overloading
SurroundDescriptive filenames, related files open

Best practices built on them: provide clarity (Single + Specific), provide context (Surround, balanced with Short), provide examples, assert and iterate.

Trap"As general as possible", "avoid examples so Copilot stays creative", "keep it lengthy": all wrong.

How context is determined

  • Inline: current file around the cursor (fill-in-the-middle) + open tabs. Closed files are not seen.
  • Chat: selection, active file, explicit # refs, @workspace/#codebase search, custom instructions, chat history.
  • Agent: decides its own reads, searches and tool calls.
  • Cloud agent: pick repo and base branch; state objective, acceptance criteria and relevant files.
  • Your code quality is context: descriptive names, comments, modular code and unit tests all improve responses.

Chat history: use and manage it

  • Earlier turns in a thread are sent with each request, so follow-ups can say "now add error handling".
  • Long histories are inefficient and costly: MS Learn says 2–3 PRUs per turn with full history vs about 1 when summarised or reset (PRU = premium request unit, now legacy billing).
  • Summarise: "Based on our previous discussion about user authentication, now add rate limiting…"
  • Reset for a new feature: new thread / /clear, restate only essentials.
  • Concise references to earlier work instead of pasting implementations.
  • Roll back irrelevant turns where supported: CLI /undo / /rewind. Cloud agent sessions can't be rewound per turn.
  • Review every output like a colleague's work.

5 · Developer productivity 10–15%

Code quality

  • Refactor: be explicit about constraints (keep public API, language version).
  • Docs: /doc inline, or README / API docs in chat.
  • Legacy modernisation: explain first (/explain), then translate in small units, then test against original behaviour.
  • Sample / mock data: specify schema, volume, realistic edge values; never real personal data.

Testing

  • /tests for unit tests of selected code; say the framework ("using Jest").
  • Integration tests need wider context: open related modules or use @workspace.
  • Ask explicitly for edge cases (nulls, empty, boundaries, errors) and meaningful assertions.
  • #testFailure / /fixTestFailure (some IDEs) to debug failing tests.

Security & performance

  • Ask Copilot to review for OWASP-style issues (injection, secrets, input validation).
  • /optimize for running time; verify with profiling, not trust.
  • Productivity framing: reduces context switching (answers in the IDE) and speeds learning of unfamiliar code.

What indemnity doesn't do

  • It's a contractual defence, not a guarantee the code is licence-clean or secure.
  • It doesn't cover modified output; once you edit a suggestion, claims about the edited code are outside it 3RD-PARTY legal analysis of the terms.

  • A Microsoft blog notes duplicate detection doesn't apply to the coding (cloud) agent 3RD-PARTY Microsoft employee blog.

What patterns can't do

  • Exclusions don't apply to symbolic links or repos on remote filesystems.
  • No pattern stops semantic leakage from the IDE (types, hover info, build config).
  • Org rules apply to that org's seat holders; repo rules apply to everyone in the enterprise working in that repo (see Topology).
  • An org "*" rule also matches files outside any Git repo (e.g. /.env).
  • Changes can take up to 30 minutes to reach IDEs; reload the window to force it.
  • Exclusion is not access control: keep OS permissions and secret scanning.
Exam angle"Exclude every .env file across all repos" → org or enterprise level, "*": key, pattern "**/.env". Repo-level settings can't reach other repos.

Copilot Memory: what differs from other features

  • Plans: "all paid Copilot plans", so not Free. Student and Max aren't named in the docs. Public preview OFFICIAL

REST API quickstart: the parts that matter

  • Three ways to call it: GitHub CLI (gh api <path>, recommended for the command line and handles auth), curl with an Authorization header, or Octokit.js (octokit.request("GET /path", {...})).
  • Auth: gh auth login (choose GitHub.com or enter a GHE host); a PAT or GitHub App user token with the scopes the endpoint needs; in Actions prefer GITHUB_TOKEN. GitHub App installation tokens expire after 60 minutes.
  • Headers: Accept: application/vnd.github+json; Authorization: Bearer <token> (token usually works too, but a JWT needs Bearer); X-GitHub-Api-Version (not covered by the quickstart).
  • Copilot-specific: some Copilot endpoints reject fine-grained PATs and GitHub App tokens. Use a classic PAT with manage_billing:copilot (or admin:enterprise for enterprise policy).

gh api /orgs/YOUR-ORG/copilot/billing

Top 22 exam traps

  1. Content exclusion is Business/Enterprise only, and exam-era docs say agent mode, CLI and coding agent ignore it.
  2. IDE prompts are not retained; outside the IDE it's 28 days.
  3. Audit log shows settings and seat changes, never prompts. Keeps 180 days.
  4. Multi-org policy conflicts: least restrictive wins for most features.
  5. IP indemnity needs Block + unmodified suggestion + Business/Enterprise (exam answer; Microsoft CCC made Block optional from 3 Apr 2026).
  6. Public-code check window is ~150 characters.
  7. Exclusion changes take up to 30 minutes; reload the IDE.
  8. Prompt files are on demand; custom instructions are always on.
  1. /new uses only the prompt as context.
  2. Inline suggestions see open tabs, not closed files.
  3. Org custom instructions only on GitHub.com (Chat, code review, cloud agent).
  4. CLI ! prefix skips the model; classic ghp_ PATs unsupported.
  5. Cloud agent and MCP on GitHub.com are off by default for orgs/enterprises.
  6. "Innovation" is not an RAI principle.
  7. Copilot is not available on GitHub Enterprise Server.
  8. Policies follow the licence; exclusions and agent opt-outs follow the repo.
  9. Several orgs: least restrictive. Several enterprises: most restrictive.
  10. Org seat assignment cancels a personal Pro/Pro+ plan (prorated refund).
  11. Copilot Memory: admin enables, user can opt out; unused memories expire after 28 days.
  12. Exclusion "*.cfg" matches anywhere; applyTo: "*.py" matches the root only.
  13. "Shot" counts examples: zero = none, one = one, few = several. No fine-tuning occurs.
  14. Free / Pro / Pro+ data is used for training by default (since 24 Apr 2026) unless opted out; Business/Enterprise never.
